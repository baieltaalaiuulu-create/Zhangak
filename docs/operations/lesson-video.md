# Видео уроков: что защищено, а что нет

Назначение документа: объяснить, какую защиту реально даёт видео-плеер Zhangak,
и зафиксировать границы, которые нельзя обещать ученику или владельцу.
Владелец процесса — технический оператор. Обновляется вместе с кодом плеера.

## Главное в одном абзаце

Zhangak защищает **доступ к уроку**, а не **сам видеофайл**. Ученик получает
идентификатор видео YouTube только после того, как сервер проверил его сессию,
активное онлайн-зачисление, публикацию и разблокировку урока. Это настоящая и
проверяемая граница. Но браузер, которому разрешено воспроизвести видео,
обязательно получает этот идентификатор — иначе embed не заработает. Поэтому
подготовленный пользователь **может** увидеть video ID в DevTools или в панели
сети. Это остаточный риск, а не дефект реализации.

## Чего нельзя писать в интерфейсе и в рекламе

Формулировки ниже запрещены, потому что они не соответствуют реализации:

- «видео невозможно скачать»;
- «ссылка полностью скрыта»;
- «защищено DRM»;
- «доступ только внутри платформы, скопировать нельзя».

Допустимая формулировка: видео открывается внутри личного кабинета, доступ
проверяет сервер, прямой ссылки в интерфейсе нет.

## Что реально работает

| Граница | Где реализована | Что проверяется |
| --- | --- | --- |
| Нормализация ссылки | `backend/src/youtube.js` | Только `watch?v=`, `youtu.be/` и `/embed/` на точных хостах YouTube. Отклоняются протокольные трюки, credentials, порт, fragment, playlist, shorts, live, канал, похожие домены и сырой HTML iframe. |
| Каноническое хранение | миграция `015`, `lessons.video_id`, `lesson_materials.video_id` | В базе лежит проверенный 11-символьный id; URL пересобирается из него. |
| Проекция для ученика | `publicLesson`, `publicLessonMaterial` | В списках уроков и материалов **нет** watch URL. Есть только `sessionPath`. |
| Выдача конфигурации | `POST /v1/platform/lessons/:id/video`, `POST /v1/platform/materials/:id/video` | Заново проверяются: сессия → роль student → `student_type = online` → активное зачисление на активный online-курс → опубликованный урок → `scan_status = 'clean'` и публикация материала → урок разблокирован. |
| Отзыв доступа | те же маршруты | Выход из аккаунта, отзыв сессии, приостановка зачисления или повторная блокировка урока немедленно прекращают выдачу конфигурации. |
| События воспроизведения | `POST /v1/platform/video-events` | Аналитика и аудит. Идемпотентны в пределах суток Asia/Bishkek. XP, звёзды и завершение урока **не** зависят от них. |
| Приватность embed | `components/student/LessonVideo.tsx` | `youtube-nocookie.com`, загрузка только после клика ученика. |
| CSP | `deploy/nginx/zhangak.conf` | `frame-src` разрешает ровно два origin YouTube. |

## Ограничения самого YouTube

Эти пункты не зависят от кода Zhangak:

1. **Unlisted-видео скрыто из поиска, но доступно любому, у кого есть ссылка.**
   Это не приватность, а отсутствие индексации.
2. **Обычный YouTube embed не является DRM.** Никакая комбинация параметров
   плеера не превращает его в защищённую доставку.
3. **Allowlist доменов** (ограничение воспроизведения списком сайтов) доступен
   только отдельным партнёрам YouTube Studio с Content Manager. Это не
   гарантированное решение для Zhangak и на него нельзя закладываться.
4. **Referer нельзя подавлять.** Встроенный плеер требует Referer; попытка его
   скрыть ломает воспроизведение.
5. **Нельзя перекрывать элементы управления** прозрачными оверлеями и нельзя
   ломать accessibility или fullscreen — это нарушает условия YouTube.

## Если понадобится настоящая защита

Это отдельный будущий проект, а не доработка текущего плеера: собственный
video hosting или CDN с подписанными короткоживущими HLS/DASH-манифестами и
лицензированным DRM (Widevine/FairPlay/PlayReady), плюс видимый водяной знак с
идентификатором ученика. **Не внедряйте это сейчас** и не смешивайте с текущей
задачей.

## Минимальный размер и адаптивность

Плеер держит **16:9 на любой ширине**. Рекомендованная YouTube область
200x200 px несовместима с этим соотношением на узком телефоне: 16:9-блок
достигает высоты 200 px только начиная с ширины 356 px. Приоритет отдан
соотношению сторон — растянутое видео хуже, чем невысокое. На 320 px плеер
занимает 288x162 px.

Инжектируемый IFrame API iframe получает атрибуты `width`/`height`
(по умолчанию 640x390), поэтому контейнер принудительно растягивает его через
`[&>iframe]:h-full [&>iframe]:w-full`; фиксированного пиксельного размера у
плеера нет и layout shift при открытии отсутствует.

Проверять нужно на 320, 360, 390, 430, 768, 844 (landscape), 1024, 1280 и
1440 px: горизонтальной прокрутки быть не должно, элементы управления не
должны перекрываться.

`npm run check:lesson-video` проверяет это **структурно, по исходному коду**.
Он не заменяет ручной проход по реальным ширинам и по клавиатуре — зелёный
результат скрипта не означает, что плеер видели на устройстве.

## Проверка выпуска

1. Администратор добавляет видео как `lesson_material` типа `video`; ссылка с
   playlist или shorts должна быть отклонена с понятной ошибкой.
2. Ученик с активным зачислением открывает разблокированный урок: до нажатия
   «Смотреть видео» запросов к YouTube в панели сети нет.
3. После нажатия видео воспроизводится с `youtube-nocookie.com`.
4. Ученик другого курса и ученик с заблокированным уроком получают 404/403.
5. В JSON `/v1/platform/lessons/:id` и `/v1/platform/lessons/:id/materials`
   нет ни одной ссылки на YouTube.
6. После выхода из аккаунта повторный запрос конфигурации возвращает 401.
7. Подделанное событие `ended` не начисляет XP и не завершает урок.
