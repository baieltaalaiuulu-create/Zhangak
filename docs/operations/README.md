# Операционная документация Zhangak

Этот раздел — точка входа для команды, которая управляет Zhangak после запуска. Он описывает **текущее первое собственное backend-решение**, а не старый Supabase-проект и не будущие разделы с пометкой «Скоро».

Не храните здесь, в задачах, скриншотах или Git-репозитории пароли, токены, строки подключения, персональные данные учеников и полные результаты тестов.

## Архитектура и домены

| Поверхность | Адрес | Назначение | Индексация |
| --- | --- | --- | --- |
| Публичная | `https://zhangak.com` | Бренд, программы, контакты и вход в продукт. | Разрешена. |
| Учебная | `https://platform.zhangak.com` | Кабинеты учеников и преподавателей, PWA. | Запрещена (`noindex`). |
| Административная | `https://admin.zhangak.com` | Управление аккаунтами и готовыми учебными модулями. | Запрещена (`noindex`). |
| Офлайн | `https://offline.zhangak.com` | Офлайн-кабинет ученика и журнал преподавателя. | Запрещена (`noindex`). |

Маршрутизация по доменам — часть безопасности, а не только дизайна. Ученик и преподаватель входят на `platform.zhangak.com`; сотрудник — на `admin.zhangak.com`. При попытке войти в неверный кабинет приложение завершает локальную сессию и предлагает правильную поверхность. Не переносите cookies или токены между доменами вручную.

Браузер работает только с same-origin BFF-маршрутами `/v1/platform/*` и `/v1/admin/*`. Они передают запросы приватному API Zhangak; PostgreSQL и API не должны быть публичными. Старый `/api/*` и старые Supabase-вызовы — выведенная из эксплуатации поверхность, а не запасной способ работы.

## Что уже является рабочим контуром

Рабочие административные разделы отмечены в меню как «Рабочие разделы»:

- обзор;
- курсы и уроки;
- группы;
- учётные записи;
- практика, вопросы и пробный ОРТ.

Разделы «Задание дня», «Рейтинг и призы», «База знаний AI», «Университеты», «Архив», «Аналитика» и «Объявления» отображаются как перенос на собственный backend. Они не должны использоваться для хранения, публикации или изменения боевых данных, пока не получат отдельный рабочий API, миграции и проверку.

Офлайн-журнал уже работает: преподаватель видит только свои назначенные
группы и может вести посещаемость, домашние задания, оценки и комментарии.
Расписание, объявления, состав группы и курс настраиваются только admin/
super-admin в «Группах».

## Общие правила работы

1. Работайте только из своего именного аккаунта. Общий логин для смены, школы или команды запрещён: он ломает аудит действий и безопасность.
2. Не изменяйте production PostgreSQL вручную и не выполняйте SQL из чата. Любое изменение схемы проходит через проверенную миграцию, а данные — через рабочий интерфейс/API.
3. Перед публикацией курса, теста, публичной цифры, даты ОРТ/ЖРТ или фото проверяйте источник, период, владельца факта и право на публикацию.
4. Не используйте «Скоро»-экраны как доказательство функции. Если функция важна для учебного процесса, сначала подтвердите её в рабочем контуре.
5. Для обычного прекращения доступа блокируйте аккаунт, а не удаляйте его. Удаление необратимо и допустимо только после проверки владельцем данных.
