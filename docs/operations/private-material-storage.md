# Приватные материалы уроков

Материалы хранятся только в собственном файловом хранилище Zhangak. Nginx не
раздаёт каталог файлов, а в базе сохраняется непрозрачный ключ объекта, не URL.

## Что может загрузить администратор

- текст урока до 500 000 символов; формулы сохраняются как LaTeX-исходник;
- ссылку на YouTube для видео (см. [Видео уроков](lesson-video.md) —
  ссылка нормализуется до проверенного video ID, и это не DRM);
- PDF до 200 MiB;
- PNG, JPEG или WebP до 30 MiB.

Загрузка проверяет фактическую сигнатуру файла, а не только расширение или
заявленный MIME-тип. Один материал занимает уникальную позицию внутри урока.

## Обязательная проверка файла

Каждый PDF или рисунок сразу после загрузки получает статус **«Ожидает
проверки»**. Он не опубликован и недоступен ученику. Администратор обязан
открыть файл в доверенной среде, проверить его и выбрать одно из действий:

1. **Подтвердить и опубликовать** — записывает кто и когда подтвердил файл,
   делает его доступным назначенным ученикам.
2. **Отклонить** — закрывает материал и удаляет его объект из хранилища.

На первом запуске это ручная проверка: на VPS нет работающего ClamAV. Нельзя
называть файл «проверенным антивирусом», пока не подключены и не мониторятся
ClamAV/очередь сканирования. После их внедрения статус `clean` должен
устанавливаться воркером сканирования, а не вручную.

## Доступ ученика

Сервис выдаёт материал только ученику с активным онлайн-зачислением на курс и
только для разблокированного урока. Файлы отдаются `inline` через
аутентифицированный endpoint, без публичной ссылки и без ключа хранилища в
ответе. Отзыв публикации или доступа к курсу немедленно закрывает просмотр.

Это **не DRM**: ученик всё ещё может сделать скриншот или сохранить данные,
которые браузер уже получил. Для заявленного в продукте водяного знака с ID
ученика нужен отдельный viewer, который рисует видимый оверлей, а для защиты
самого PDF — серверная генерация водяного знака/лицензированный DRM. Не
рассчитывайте на текущую реализацию как на запрет копирования.

## Подготовка VPS

Путь из `ZHANGAK_STORAGE_ROOT` должен быть отдельным приватным каталогом на
втором томе, принадлежать пользователю `zhangak-api` и не иметь чтения для
остальных пользователей. Для текущего сервера:

```bash
install -d -o zhangak-api -g zhangak-api -m 0750 /mnt/HC_Volume_106608581/zhangak-materials
```

В `/etc/zhangak-api/zhangak-api.env` добавляется только:

```ini
ZHANGAK_STORAGE_ROOT=/mnt/HC_Volume_106608581/zhangak-materials
```

После изменения переменных сервис перезапускается при активации API-релиза.
Настройка Nginx допускает multipart-запрос до 210 MiB, но сервер ещё раз
строго применяет лимиты 200/30 MiB.

## Проверка выпуска

1. Администратор создаёт тестовый урок и загружает небольшой PDF.
2. API возвращает `202` и `scanStatus: pending`; ученик не видит материал.
3. После «Подтвердить и опубликовать» назначенный ученик видит его на странице
   урока, а другой ученик и ученик без доступа получают отказ.
4. После «Отклонить» файл не открывается, а объект отсутствует в хранилище.
5. Регулярный backup обязан включать каталог материалов и базу PostgreSQL в
   одном согласованном плане восстановления.
