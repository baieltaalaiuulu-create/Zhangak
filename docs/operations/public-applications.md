# Публичные заявки и ручная оплата

## Что происходит после формы

1. Гость на `zhangak.com` вводит имя, номер WhatsApp, город и опубликованный
   курс. Заявка получает номер и сохраняется в PostgreSQL Zhangak.
2. Гость открывает готовую ссылку WhatsApp. Это не заменяет запись заявки:
   номер в сообщении связывает переписку с карточкой в кабинете.
3. Manager, admin или super_admin работают с очередью на
   `admin.zhangak.com/manager` или `admin.zhangak.com/admin/applications`.
4. После ручной сверки оплаты admin/super_admin создаёт аккаунт ученика в
   разделе «Ученики», выбирает его в заявке и подтверждает оплату.
5. Только этот последний шаг в одной транзакции создаёт активное зачисление
   на выбранный курс. Без активного зачисления учебные материалы недоступны.

## Статусы

| Статус | Значение | Кто переводит |
| --- | --- | --- |
| Новая | Форма принята, коммуникация ещё не зафиксирована | manager/admin |
| Связались | Команда начала общение | manager/admin |
| Ожидает оплаты | Реквизиты/стоимость отправлены | manager/admin |
| Ожидает подтверждения | Оплата заявлена, нужна сверка | manager/admin |
| Зачислен | Оплата подтверждена и создано active-зачисление | admin/super_admin |
| Отклонена / Отменена | Обращение закрыто без доступа | manager/admin |

История статусов, внутренних заметок и подтверждения оплаты хранится в
`public_application_events`; изменения дополнительно оставляют запись в общем
`audit_log`. Заметки не видны посетителю.

## Правила для команды

- Не отправляйте пароль по WhatsApp в открытом виде. Создайте аккаунт,
  передайте временный пароль безопасным согласованным способом и попросите
  ученика сменить его при первом входе, когда этот сценарий будет включён.
- Перед подтверждением сравните имя, курс, формат (online/offline) и факт
  оплаты. Тип обучения аккаунта должен совпадать с форматом курса.
- У ученика может быть только один текущий курс. Ошибка «у ученика уже есть
  текущий курс» означает, что сначала нужно завершить или отменить прежнее
  зачисление по утверждённой процедуре.
- Manager может вести заявку и ставить статусы, но не создаёт доступ. Это
  ограничение защищает ручную оплату от случайной активации.
- Не храните в заметках номер карты, документ оплаты или другие лишние
  платёжные персональные данные. Достаточно факта сверки и служебной пометки.

## Техническая граница

Публичный BFF принимает только `/v1/public/courses` и
`/v1/public/applications` на `zhangak.com`. Внутренние queue-маршруты требуют
HttpOnly-сессию и роль manager/admin/super_admin на admin-поддомене. Приём
заявок ограничен пятью попытками с одного IP за десять минут; это защита от
простого спама, а не замена антиспам-провайдера. Production API должен
содержать `https://zhangak.com` в `ALLOWED_ORIGINS`, иначе BFF намеренно
отклонит публичный POST.
