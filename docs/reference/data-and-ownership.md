# Матрица данных и ответственности

Документ отвечает на четыре вопроса: какие данные есть, кто их создаёт, кто
проверяет и когда они должны обновляться.

## Бизнес- и учебные данные

| Данные | Создаёт/изменяет | Проверяет | Когда обновлять | Где |
| --- | --- | --- | --- | --- |
| Публичные факты, контакты, цены | владелец бренда/editor | владелец бизнеса | до каждой кампании и при изменении | `docs/marketing/`, landing |
| Заявки и WhatsApp-статус | manager/admin | admin | ежедневно в период набора | очередь заявок |
| Подтверждение оплаты | admin/super-admin | ответственный за оплату | после ручной сверки | заявка + enrollment |
| Аккаунт и роль | super-admin; admin только student | super-admin | создание, уход, ежемесячный review | users/profiles |
| Курс и урок | admin/super-admin | методист | до публикации и при изменении программы | courses/lessons |
| Материалы | admin/super-admin | методист + file scan | до публикации, при новой версии | lesson_materials/private storage |
| Тест и вопрос | admin/super-admin | методист/editor | до публикации и после жалобы | practice tables |
| Группа и состав | admin/super-admin | учебный администратор | при наборе/уходе | groups/group_students |
| Расписание/объявление | admin/super-admin | администратор группы | при изменении занятия | offline classroom |
| Посещаемость | назначенный teacher | admin при споре | после каждого занятия | attendance |
| Домашняя работа | teacher | методист/admin | по учебному плану | homework/submissions |
| Оценка/комментарий | teacher | admin при споре | после проверки работы | grades/comments |
| Прогресс, XP, звёзды | только backend | тесты/оператор | автоматически | attempts/xp awards |
| AI consent/history | ученик + backend | технический оператор по инциденту | при согласии/сообщении | ai tables |
| Университеты/пороги | назначенный редактор | официальный источник | перед приёмной кампанией | university catalog |

## Системные данные

| Данные | Источник | Ручное редактирование | Хранение/контроль |
| --- | --- | --- | --- |
| Session и refresh hash | auth API | запрещено | revoke при password/role/block |
| Audit log | backend | запрещено | регулярный access review |
| Migration ledger | migrator | запрещено | checksum + CI clean restore |
| Backup | systemd timer | не править архив | checksum, restore-drill, off-server copy |
| Release SHA | build/deploy | не подменять | health web/API должен совпадать |
| Provider secrets | root-owned env | только оператор | rotation, никогда в Git/browser |

## Классификация чувствительности

| Класс | Примеры | Правило |
| --- | --- | --- |
| Публичные | опубликованные программы, подтверждённые контакты | можно публиковать после проверки источника |
| Внутренние | черновики, внутренние комментарии, audit summary | только соответствующим ролям |
| Персональные | ФИО, email, телефон, оценки, посещаемость | минимальный доступ и approved purpose |
| Секретные | пароль, token, DB URL, provider key, password hash | никогда не логировать/отправлять/коммитить |
| Учебно-защищённые | правильные ответы до submit, закрытые материалы | только серверная граница и private delivery |

## Регулярный календарь

### Ежедневно

- обработать новые заявки и спорные ошибки доступа;
- проверить занятия/сроки на ближайшие сутки;
- убедиться, что backup timer завершился успешно;
- проверить health четырёх доменов и свободное место.

### Еженедельно

- разобрать жалобы на вопросы и просроченные черновики;
- проверить активные группы, назначения и ближайшие публикации;
- просмотреть ошибки API без копирования персональных данных.

### Ежемесячно

- super-admin проверяет роли и неактуальные аккаунты;
- оператор проверяет restore, зависимости, TLS и capacity;
- владелец контента проверяет публичные цены/адреса/программы.

### Перед учебным годом или кампанией

- официально сверить правила, даты и программу ОРТ/ЖРТ;
- обновить курсы, пороги университетов и маркетинговые факты;
- проверить согласия на фото/отзывы и юридические документы;
- выполнить полный тестовый путь каждой роли.

## Что не хранить в Git

Списки реальных учеников, пароли, экспорт оценок, документы оплаты, backup,
production `.env`, приватные PDF и provider keys. В Git хранится только схема,
код, шаблоны и инструкции без реальных секретов/персональных данных.
