# Внедрение учебного Roadmap

## Цель

Roadmap — основной путь **онлайн-ученика**. Он визуально читается снизу вверх:
пройденные шаги расположены ниже, текущий — в центре, будущие — выше. Это не
заменяет каталог уроков и не применяется к отдельному офлайн-интерфейсу.

## Правила, подтверждённые продуктом

- У ученика один активный курс: `online` **или** `offline`; гибридного режима нет.
- Онлайн-курс — самостоятельный путь из материалов, уроков и тестов. Офлайн
  работа идёт через группы, журнал преподавателя, посещаемость и задания.
- Урок открывается только после серверной проверки предыдущего шага. Клиент
  никогда не определяет блокировку сам.
- Обычный урок завершается явным действием ученика; тестовый/привязанный к
  практике урок — только после серверной сдачи попытки.
- Каждый юнит показывает процент завершения и от 0 до 3 звёзд:
  `0–49 = 0`, `50–74 = 1`, `75–89 = 2`, `90–100 = 3`.
- XP за урок выдаётся единожды сервером. Повторные прохождения и сброс
  тренажёра не меняют уже выданный XP.

## Технический план

1. **Схема Roadmap — начат.**
   Миграция `012_course_roadmaps.sql` создаёт `course_units` и
   `course_unit_lessons`. Композитные внешние ключи не позволяют добавить урок
   в юнит другого курса; позиция и номер юнита уникальны внутри курса.
2. **API Roadmap.**
   `GET /v1/platform/roadmap` вернёт только активный онлайн-курс ученика,
   опубликованные юниты и безопасную проекцию уроков. Сервер посчитает
   `completedLessons`, `completionPercent`, `starCount`, `isLocked` и
   `isCurrent`; ключи ответов, прямые ссылки к закрытым материалам и служебные
   поля в ответ не попадут.
3. **Клиент онлайн-платформы.**
   Новый экран `/student/online/roadmap` вызовет собственный BFF/API, отрисует
   восходящий путь и автоматически позиционирует текущий шаг. Главная и
   Roadmap сохранят разные роли в навигации; Тренажёр остаётся отдельной
   вкладкой.
4. **Администрирование.**
   Только `admin` и `super_admin` смогут создавать юниты, менять их порядок,
   добавлять уроки и публиковать. Любая мутация получает аудит.
5. **Контент.**
   После админского UI существующие уроки и проверенные материалы будут
   разложены по юнитам. До публикации курс с неполной картой не виден ученику.
6. **Проверка и релиз.**
   Unit/contract тесты, изолированная PostgreSQL-проверка миграций, сценарии
   блокировок и мобильный скриншотный QA; затем отдельный preprod-релиз.

## Границы безопасности

- Только собственный Node.js API и PostgreSQL; Supabase не возвращается.
- `correct_answer` и `explanation` остаются серверными до финальной сдачи.
- Все данные Roadmap привязаны к активному `course_enrollments` ученика.
- Админские данные не доверяются браузеру: порядок, публикация и доступ
  валидируются сервером и фиксируются в `audit_log`.
